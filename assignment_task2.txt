Functional Requirements
Functional requirements define the specific behaviours and functions the SavePlate system must provide to support its six core use cases. Each requirement below is identified by a unique ID, specifies the system's observable behaviour, provides the justification for its inclusion, and is assigned a MoSCoW priority M (Must Have), S (Should Have), or C (Could Have) to guide iterative development planning. Requirements are grouped by use case and student responsibility as established in the Task 2 assignment brief.

2FA setup, donation conversion, claiming listings, plan confirmation, notification read-state
C - Could Have

Non-Functional Requirements
Non-functional requirements describe the quality standards and system constraints that SavePlate must meet. These requirements focus on how the system operates rather than what features it provides. They cover aspects such as performance, security, usability, reliability, scalability, and maintainability. Each requirement also includes measurable criteria so that the system can be properly evaluated during testing. Unless stated otherwise, these requirements apply to the entire system.
Table 1.1.21Non-Functional Requirements
NFR Category: Performance
NFR ID
Requirement
Rationale
Measurable Metric
NFR-PE-1
The system must load the Food Inventory dashboard within 3 seconds for users who have up to 200 items, using a normal internet connection (at least 10 Mbps).
The inventory page is the most frequently accessed part of the system. If it takes too long to load, users may lose interest or leave the application.
Page load time ≤ 3 seconds under normal conditions
NFR-PE-2
The system must return API responses for data requests (such as inventory, browse, notifications, and analytics) within 1.5 seconds when up to 50 users are accessing the system at the same time.
Fast API responses are important to ensure smooth interaction. Slow responses can cause delays when users navigate or perform actions.
API response time ≤ 1.5 seconds with 50 concurrent users
NFR-PE-3
The system must run the daily background process that checks for expiring items and sends alerts within 5 minutes of the scheduled time.
Expiry notifications must be delivered on time. Delays can cause users to miss important reminders, leading to wasted food.
Background process completes within 5 minutes of schedule

Table 1.1.25Scalability
NFR Category: Scalability
NFR ID
Requirement
Rationale
Measurable Metric
NFR-SC-1
The MongoDB database schema shall be designed to support a minimum of 1,000 users, each with up to 500 food inventory items, without requiring structural schema changes; queries on the foodItems collection shall use indexed fields (userId, expiryDate, status, category) to maintain query performance at this scale.
Index design decisions made during development are difficult to change in production. Defining the required indexes now, based on the most common query patterns (filtering by userId, sorting by expiryDate, filtering by status), prevents performance degradation as data volume grows.
Required indexes defined for userId, expiryDate, status, and category fields in foodItems collection
NFR-SC-2
The Vue.js frontend application shall be built as a Single Page Application (SPA) with code splitting enabled, such that the initial JavaScript bundle size does not exceed 500 KB (gzipped), and individual route chunks are loaded on demand rather than bundled into a single file.
A monolithic JavaScript bundle forces users to download the entire application before any content renders. Code splitting allows the initial load to deliver only what is needed for the landing/login page, with route-specific code loaded lazily as the user navigates.
Initial gzipped JS bundle ≤ 500 KB; route-level code splitting implemented

Table 1.1.26Maintainability
NFR Category: Maintainability
NFR ID
Requirement
Rationale
Measurable Metric
NFR-MA-1
The Express.js backend codebase shall be organised using a layered architecture separating routes, controllers, services, and data models into distinct directories; no business logic shall be placed directly inside route handler functions.
Separation of concerns reduces coupling and makes the codebase easier to test, modify, and extend. Business logic embedded in route handlers is a common anti-pattern that makes unit testing impossible and future feature additions unnecessarily difficult.
Codebase structure: /routes, /controllers, /services, /models directories present and correctly used
NFR-MA-2
All source code shall be version-controlled using Git and hosted on the team's designated GitHub repository (as established in Task 1); each meaningful feature or fix shall be committed with a descriptive commit message, and the main branch shall only receive changes via pull requests reviewed by at least one team member.
Version control is a non-negotiable professional standard. The pull-request workflow ensures code review occurs before integration, reducing bugs reaching the main branch and creating a documented history of all changes which also satisfies the assignment's requirement for evidence of teamwork.
100% of code changes committed to GitHub; pull-request workflow followed for main branch

[Epic 2] Household Food Inventory Management
Feature/Functionality:
Allow authenticated household users to maintain a complete and accurate digital record of all food items stored in their household including item name, quantity, expiry date, category, and storage location. Users can add new items, edit existing records, mark items as used or consumed, and seamlessly convert near-expiry items into donation listings. The inventory serves as the central data source for expiry alerts, meal planning suggestions, donation management, and food analytics across the entire SavePlate platform.

Table 1.2.16User Story – Add a New Food Item to Inventory
User Story
As an authenticated household user,
I need the ability to add a new food item to my personal SavePlate inventory by entering its name, quantity, expiry date, food category, and optional storage location and notes,
so that the system has an accurate and up-to-date record of my household food stock that can be used for expiry alerts, meal planning, and donation management.
Acceptance Criteria
Given the user is logged in and navigates to the 'Food Inventory' section, then clicks the 'Add Food Item' button,

When the user completes the form by entering the item name (required), quantity (required), expiry date (required), food category (required e.g., Vegetables, Dairy, Canned, Frozen, Bakery), storage location (optional e.g., Fridge, Freezer, Pantry), and any additional remarks, then submits the form,

Then the system shall validate all required fields, reject the submission with an inline error message if any required field is missing or if the expiry date is set to a past date, and on valid input save the new food item document to the foodItems MongoDB collection with status set to 'available', then immediately display the new item in the inventory list and show a success toast notification: 'Food item added successfully.'
MoSCoW Priority
M - Must Have
Adding food items is the foundational action of the entire inventory system. Every other feature in SavePlate expiry alerts, meal planning, donation listings, and analytics depends on food items being recorded here. Without this capability the platform has no data to operate on.

Use Case 6: Plan Weekly Meals (Adrienne Kayana Wistara Lie)
Table 1.2.123Epic 2 – Inventory Based Weekly Meal Planning
[Epic 2] Inventory-Based Weekly Meal Planning
Feature/Functionality:
Enable authenticated household users to plan their meals for the week using a calendar-based interface that is directly integrated with their current food inventory. The system suggests recipes based on available ingredients (prioritising items nearing expiry), allows users to create and save custom meal plans, and automatically reserves the required inventory quantities and schedules meal reminders helping users consume food before it expires and reduce household food waste.

Table 1.2.124User Story – View Weekly Meal Planning Calendar
User Story
As an authenticated household user with an updated food inventory,
I need the ability to access a weekly meal planning calendar that displays the current week's meal slots (breakfast, lunch, dinner, and snacks for each day) alongside my current inventory,
so that I can have a structured overview of my planned meals for the week and identify which days still need a meal assigned.
Acceptance Criteria
Given the user is logged in, has at least one food item recorded in their inventory, and navigates to the 'Plan Weekly Meals' section from the dashboard,

When the meal planning calendar page loads,

Then the system shall display a 7-day calendar view for the current week with four meal slots per day (Breakfast, Lunch, Dinner, Snacks), show which slots have already been assigned a meal (displaying the meal name), highlight empty slots as available for planning, and display the user's current inventory list in a side panel filtered to show items expiring soonest first.
MoSCoW Priority
M - Must Have
The weekly calendar view is the foundational screen for all meal planning actions. Without this view, users cannot create, modify, or review their meal plan, making all other user stories in this epic dependent on it.
Tasks
Design the Meal Planner page layout in Vue.js: a 7-column calendar grid (one per day) with 4 meal slot rows, plus a right-side inventory panel
Create a MealSlot component displaying: day label, meal type (Breakfast / Lunch / Dinner / Snacks), assigned meal name (if any), and an 'Add Meal' button for empty slots
Create GET /api/mealplans/week endpoint in Express.js that retrieves the user's meal plan for the current ISO week (or creates an empty plan if none exists)
Create GET /api/items/inventory?sort=expiryDate&order=asc endpoint to retrieve inventory items sorted by soonest expiry for the side panel
Highlight inventory items expiring within 3 days with a warning badge in the side panel to encourage their inclusion in meals
Implement week navigation controls (Previous Week / Next Week) with corresponding data fetches
Persist the meal plan document in the mealPlans MongoDB collection keyed by userId and weekStartDate (Monday of the ISO week)

Table 1.2.125User Story – Add Meals Manually or via Recipe Suggestions
User Story
As an authenticated household user on the meal planning calendar,
I need the ability to add a meal to any empty slot either by typing a custom meal name or by selecting from a list of suggested recipes generated based on my current inventory with recipes prioritising ingredients nearing their expiry date,
so that I can efficiently plan meals that make use of the food I already have before it expires, minimising waste and reducing the need for additional grocery shopping.
Acceptance Criteria
Given the user is on the Meal Planner page and clicks the 'Add Meal' button on any empty meal slot, and the user's inventory contains at least two food items,

When the user either (a) types a custom meal name into the text input and clicks 'Save', or (b) views the suggested recipes list and selects one,

Then the system shall: for option (a) save the custom meal name to the selected slot in the meal plan; for option (b) save the selected recipe name to the slot AND link all matching inventory items required by the recipe to the meal entry. In both cases, the calendar shall update immediately to show the new meal in the assigned slot.
MoSCoW Priority
M - Must Have
Adding meals to the plan is the primary action within this use case. A meal planner that only shows an empty calendar without the ability to assign meals provides no functional value. Recipe suggestions are included at Must Have level because they directly serve the use case's core purpose of using existing inventory.
Tasks
Build an 'Add Meal' modal/drawer in Vue.js triggered by clicking an empty meal slot, containing: (1) a free-text input for custom meal name, (2) a 'Suggested Recipes' section below
Create GET /api/recipes/suggest endpoint in Express.js that queries the user's inventory items (sorted by expiryDate ascending) and matches them against a static recipe seed dataset or simple ingredient-matching algorithm
Recipe suggestion algorithm: for each recipe in the dataset, count how many required ingredients are present in the user's current inventory sort suggestions by highest match count, prioritising recipes that use the most items expiring soonest
Build a RecipeSuggestion card component showing: recipe name, matched ingredients list (highlighted in green), and unmatched ingredients (greyed out)
Create PATCH /api/mealplans/:planId/slots/:slotId endpoint to save the meal assignment (custom name or recipe name + linked ingredient IDs)
Implement ingredient linking: when a recipe is selected, store the IDs of matching inventory items in the meal slot's linkedFoodItems array
Update the calendar slot component to display the newly assigned meal name immediately upon save (optimistic UI update)
Allow the user to remove or replace a meal from a slot via an edit/delete icon on assigned slots

Table 1.2.126User Story – Confirm Meal Plan and Reserve Inventory
User Story
As an authenticated household user who has completed assigning meals to the weekly calendar,
I need the ability to confirm and save my weekly meal plan, which will automatically mark the required inventory items as 'reserved' for those meals and schedule a daily reminder notification for each planned meal,
so that I do not accidentally use or donate ingredients that are already allocated to a meal, and so that I am reminded each day to prepare the planned meals before the ingredients expire.
Acceptance Criteria
Given the user has assigned at least one meal to the weekly calendar and clicks the 'Confirm Plan' button,

When the user reviews the confirmation summary (listing all planned meals and their linked inventory items) and clicks 'Save Plan',

Then the system shall save the completed meal plan to the database, update the status of all linked inventory items to 'reserved' (preventing them from appearing as available for donation or other uses), schedule a notification for each assigned meal slot at a default reminder time (e.g., 7:00 AM on the meal day), and display a success message: 'Your meal plan for this week has been saved.'
MoSCoW Priority
S - Should Have
Confirming the plan and reserving inventory is important for maintaining data integrity across the system preventing the same ingredient from being used in a meal plan and listed for donation simultaneously. However, a basic save function without inventory reservation can serve as a simpler initial release of the meal planner.
Tasks
Build a 'Confirm Plan' summary screen in Vue.js that lists all assigned meal slots and their linked ingredients before final save
Create POST /api/mealplans/:planId/confirm endpoint in Express.js
In the confirm endpoint: validate that all linked food items still have status 'available'; if any are no longer available, return a warning listing the affected items
Perform a bulk status update in MongoDB: set status = 'reserved' on all foodItems documents whose _id is in any linkedFoodItems array in the confirmed plan
Create notification documents in bulk for each confirmed meal slot: { userId, type: 'meal_reminder', message: 'Reminder: [Meal Name] is planned for [Day] [Meal Type]', scheduledFor: [meal day at 07:00] }
Handle conflict scenario: if an ingredient was marked as used or donated after being added to the plan but before confirmation, display a warning and suggest re-assigning the affected meal slot
•  Display the confirmed plan in a read-only summary view accessible from the dashboard, with an 'Edit Plan' option that reverts reservations if the user modifies the plan

Table 1.2.127User Story – Receive Meal Planning Reminders from Expiry Alerts
User Story
As an authenticated household user with an active food inventory,
I need the ability to receive a system-generated suggestion to plan a meal whenever an inventory item is flagged as nearing its expiry date (within 2 days), prompting me to either add it to the weekly meal plan or convert it to a donation,
so that I am proactively guided to act on expiring ingredients before they go to waste, even if I have not opened the meal planner myself.
Acceptance Criteria
Given the user has an inventory item whose expiryDate is within 2 days of the current date and the item has not yet been assigned to a meal plan or marked for donation,

When the SavePlate system runs its scheduled daily expiry check (background job),

Then the system shall generate a notification for the user of type 'expiry_meal_suggestion' with the message: '[Item Name] expires in [N] day(s). Consider adding it to your meal plan or listing it for donation.' The notification shall include quick-action deep links to the Meal Planner and the Browse/Donate page for that item.
MoSCoW Priority
C - Could Have
Proactive expiry-based meal suggestions are a desirable smart feature that enhances the system's intelligence and user experience, but the core meal planning workflow functions independently. This can be introduced in a later iteration once the base notification system and meal planner are stable.
Tasks
Create a scheduled background job (using node-cron or a similar scheduler) that runs daily at a fixed time (e.g., 08:00 AM) on the Express.js server
In the job: query all foodItems where expiryDate <= today + 2 days AND status = 'available' AND no existing meal_suggestion notification was sent in the last 24 hours for that item
For each qualifying item, create a notification document: { userId, type: 'expiry_meal_suggestion', itemId, message: '[Item] expires in [N] day(s). Add to meal plan or donate.', deepLinks: { mealPlanner: '/planner', donate: '/browse?itemId=...' }, isRead: false, createdAt: now }
Ensure the job is idempotent: check for an existing unread notification for the same item before creating a duplicate
Build a notification card variant in Vue.js for type 'expiry_meal_suggestion' that displays the item name, days remaining, and two action buttons: 'Add to Meal Plan' and 'List for Donation'
Log job execution results (items processed, notifications created) to server console for monitoring purposes
